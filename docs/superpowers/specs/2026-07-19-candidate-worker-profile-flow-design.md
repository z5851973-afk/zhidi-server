# 候选师傅资料查看与完成选择流程设计

日期：2026-07-19

## 目标

修复“选择候选师傅”页面只能添加、不能查看资料，也没有明确下一步的问题。业主必须能够在加入候选前查看服务器真实工人资料和施工案例，并在选完后进入“我的家”继续跟踪需求。

## 用户流程

1. 业主创建服务需求后进入“选择候选师傅”。
2. 点击师傅卡片的非按钮区域，进入该师傅的真实资料详情。
3. 详情展示姓名、工种、服务城市、工龄、日薪、自我介绍和服务器施工案例；加载失败显示真实错误及重试，不回退 Mock。
4. 列表与详情均可执行“添加候选”；同一师傅不得重复添加，最多选择三人。
5. 添加成功后，列表候选数量和卡片“已选”状态立即同步。
6. 页面底部固定显示“完成选择（已选 X/3）”；未选任何人时禁用。
7. 点击完成选择后返回“我的家”，刷新服务器需求并打开或突出显示本次需求，业主继续查看候选接单、上门时间与报价状态。

## 页面与状态

- 候选卡片整体可点击，并提供明确的“查看资料”语义；右侧按钮只负责添加，避免点击冲突。
- 已选卡片保留“已选”状态，不再次调用添加接口。
- 添加中只锁定当前师傅按钮并显示加载状态。
- 达到三人后，其余添加按钮禁用并提示“最多选择 3 位候选师傅”，但仍允许查看资料。
- 完成选择的返回结果包含 `requestId` 和已选工人 ID，由上层导航到“我的家”并触发服务器刷新。

## 数据边界

- 工人列表使用公开工人目录 API。
- 工人详情和案例使用公开真实 API。
- 候选添加使用服务请求候选 API，只有服务器成功后更新选中状态。
- 正式路径不使用本地 Mock、Picsum 或本地假成功。

## 错误处理

- 工人详情或案例加载失败：保留当前页面，显示中文错误和重试入口。
- 添加候选失败：不改变已选状态，显示服务器中文错误。
- 需求失效、登录失效或候选已满：显示对应中文提示，并刷新服务需求状态。
- 连续点击通过请求中集合防止重复提交。

## 验收

- 点击每张候选卡片均能打开对应真实师傅资料。
- 详情展示与工人端保存的资料及案例一致。
- 从详情添加后返回列表，候选数量和已选状态一致。
- 最多添加三位，不能重复添加。
- 完成选择后进入“我的家”并看到本次真实服务需求。
- 强停重启或换手机登录后，候选状态由服务器恢复。
- Widget 测试覆盖打开详情、添加同步、三人上限和完成选择导航；真机完成一次公网闭环复验。
