# 业主资料与地址簿完善设计

## 目标

把业主的账号资料、常用服务地址和装修需求拆成三个清晰的数据边界，让业主换手机后资料仍可从服务器恢复，并让预约自动带入可靠的联系人和上门地址。

## 当前问题

- 个人中心固定展示“已实名认证”，但系统尚未接入实名认证能力。
- 编辑资料只能修改姓名和城市，手机号、头像、性别等账号信息没有完整展示。
- `owner_profiles` 同时承载姓名、城市和房屋地址、装修类型、面积，个人资料与具体房屋需求混在一起。
- 地址管理目前只写入 Flutter 本地状态，卸载应用或更换手机后无法恢复。
- 创建服务需求仍可能回退使用个人资料里的单一地址，无法稳定选择常用地址。

## 产品边界

### 个人资料

个人资料包含：头像（选填）、姓名或称呼（必填）、手机号（登录账号，只读）、性别（选填）和所在城市（必填）。手机号已经过验证码登录验证，页面显示“手机号已验证”。在没有接入第三方实名服务前，不展示“已实名认证”。

### 常用地址

地址簿独立保存联系人、联系电话、省份、城市、区县、详细地址和默认地址标记。一个业主可维护多个地址，但最多只有一个默认地址。首次创建地址时自动成为默认地址；删除默认地址后，剩余地址中的第一条自动成为默认地址。

### 房屋与装修需求

装修类型、房屋面积、小区和门牌号属于具体装修需求或项目，不再作为个人资料完整度条件。现有 `owner_profiles.decoration_type/address/area` 字段暂时保留以兼容生产历史数据，不删除、不清空；新页面和新预约链路不再把它们当成账号资料编辑项。

## 页面与流程

### 首次资料完善

验证码登录后，首次资料页只要求填写姓名和所在城市；手机号只读展示，性别与头像可跳过。提交成功后从服务器回读，避免本地假成功。地址可在首次资料完成后通过清晰入口补充，不阻塞进入首页。

### 个人中心

个人中心头部展示头像、姓名、所在城市和“手机号已验证”。资料不完整时展示完成度提示；点击进入“个人资料”页。页面继续保留“地址管理”入口，但地址数量和默认地址应来自服务器。

### 编辑资料

编辑页展示头像、姓名、手机号、性别和所在城市。手机号不可编辑；头像上传复用现有 `/api/v1/storage/upload`，使用 `owner-avatar` 分类。只有服务器 PUT 成功并 GET/响应回读后才更新本地状态。

### 地址管理

地址页支持真实的列表、空状态、新增、编辑、删除和设为默认。保存失败时保留表单内容并显示中文错误；删除前二次确认。列表中手机号脱敏展示，编辑页内展示完整号码。

### 预约带入

创建服务需求或预约时优先带入默认地址的城市和完整地址，同时带入默认联系人和联系电话。没有默认地址时，引导业主先选择或新增地址；业主可以为本次需求临时修改，但临时修改不会静默覆盖地址簿。

## 后端与数据

### 业主资料

为 `owner_profiles` 增加可空字段 `avatar_url` 和 `gender`。继续使用：

- `GET /api/v1/owners/me`
- `PUT /api/v1/owners/me`

响应保留历史房屋字段以兼容旧客户端；`profileComplete` 改为姓名和城市均非空。性别只接受 `MALE`、`FEMALE`、`UNDISCLOSED` 或空值；头像只接受平台上传路径。

### 地址簿

新增 `owner_addresses` 表，字段包括 `id`、`owner_user_id`、`recipient`、`phone`、`province`、`city`、`district`、`detail`、`is_default`、版本和审计时间。所有查询和修改都按当前 JWT 业主隔离，禁止跨账号读取或修改。

新增接口：

- `GET /api/v1/owners/me/addresses`
- `POST /api/v1/owners/me/addresses`
- `PUT /api/v1/owners/me/addresses/{addressId}`
- `DELETE /api/v1/owners/me/addresses/{addressId}`
- `PUT /api/v1/owners/me/addresses/{addressId}/default`

服务层在事务内保证单一默认地址。数据库迁移只新增字段和表，不重建数据库、不删除生产数据。

## 兼容与隐私

- 旧客户端仍可读写原有五个业主资料字段。
- 新客户端读取旧账号时，以已有姓名和城市判断账号资料是否完成；旧房屋字段仍保留供历史项目显示。
- 个人中心和地址列表脱敏手机号；预约快照仅对订单双方在有效订单阶段展示。
- 本轮不接身份证实名认证、不存身份证号或证件照片。
- 本轮不接入营业执照相关能力。

## 错误处理

- 未登录或令牌失效统一返回登录页，不本地假保存。
- 服务端校验姓名、城市、手机号和地址长度，Flutter 同步展示明确中文提示。
- 上传失败不影响其他文字资料；用户可不上传头像继续保存。
- 网络失败时保留当前页面和输入内容，允许重试。

## 验证标准

- 后端迁移、资料接口、地址 CRUD、默认地址唯一性和跨业主权限测试通过。
- Flutter API 模型、首次资料、个人资料、地址管理和预约带入 Widget/状态测试先失败后通过。
- 强停重启和清除应用数据后，重新登录仍能从服务器恢复资料与地址。
- Android 业主端静态检查、全量测试和 APK 构建通过。
- 在模拟器走通：登录 → 完善资料 → 新增默认地址 → 编辑资料 → 发起需求并自动带入地址。
