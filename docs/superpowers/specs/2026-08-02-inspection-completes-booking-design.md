# 验收通过自动完成订单设计

## 目标

业主通过当前工种的验收后，该预约立即从施工中的 `HIRED` 推进为 `COMPLETED`。工人端下一次刷新时自动从“进行中”移动到“已完成”，三端以服务端订单状态为唯一事实来源。

## 状态规则

- 验收只能由当前预约的工人发起；业主不能创建验收节点，也不能把待验收节点推进为验收中。
- 只有工人发起后，业主才能对 `INSPECTING` 节点提交通过或不通过。
- 只有业主对 `INSPECTING` 的当前工种验收节点提交 `PASS` 时才推进订单。
- 订单下当前工种节点全部为 `PASSED` 后，预约由 `HIRED` 变为 `COMPLETED`。
- `FAIL`、其他工种历史节点或尚未全部通过的当前工种节点不会完成订单。
- `COMPLETED` 订单不再允许新增施工节点、重复发起验收或继续提交施工日报。
- 验收完成后付款仍未结束，因此支付订单允许从 `HIRED` 或 `COMPLETED` 创建；资金状态继续由支付订单、结算和质保金账本表达。

## 双端交互与文案

### 业主端

- 施工中的项目主按钮使用“验收进度”，不得出现“申请验收”或“发起验收”。
- 尚无验收节点时显示“师傅尚未发起验收”。
- 节点为 `PENDING` 时显示“等待师傅发起验收”，不提供通过、不通过或发起按钮。
- 节点为 `INSPECTING` 时显示“待您验收”，提供“去验收”，业主可以选择通过或要求整改。
- 节点为 `FAILED` 时显示“等待师傅整改并重新发起”，业主只能查看上次验收记录。
- 节点为 `PASSED` 时显示“验收已通过”，业主可以查看验收记录。
- 首页验收卡片使用“查看进度 >”，点击始终只进入业主验收进度页；具体可执行动作由节点状态决定。

### 工人端

- 当前工种施工节点为 `PENDING` 时显示“申请验收”。
- 节点为 `FAILED` 时显示整改意见，并提供“申请重新验收”。
- 节点为 `INSPECTING` 时显示“等待业主验收”，不可重复申请。
- 节点为 `PASSED` 时只显示通过状态和记录，不再允许施工或验收操作。

### 服务端权限

- 创建验收节点和申请验收接口继续要求 `WORKER` 角色，并校验操作者是该预约工人。
- 提交验收结果接口继续要求 `OWNER` 角色，并校验操作者是该预约业主。
- Flutter 文案和按钮不能替代服务端权限；后端测试必须覆盖业主无法发起、工人无法代替业主验收。

## 兼容与历史数据

- 数据库状态约束增加 `COMPLETED`。
- 对历史 `HIRED` 订单，仅当当前工种对应验收节点已通过时回填为 `COMPLETED`，避免无关旧节点导致误归档。
- Flutter 将服务端 `COMPLETED` 映射到 `WorkerOrderStatus.completed`；已完成列表保留订单摘要，不展示施工操作。

## 验证

- 后端测试覆盖通过验收推进、验收失败不推进、付款兼容 `COMPLETED`。
- 后端权限测试覆盖业主无法创建/申请验收、非预约工人无法申请、工人无法提交业主验收结果。
- 迁移测试覆盖状态约束与历史回填。
- Flutter 测试覆盖 `COMPLETED` 只出现在“已完成”而非“进行中”。
- Flutter 业主端测试覆盖施工中首页没有“申请验收”，无节点/PENDING/INSPECTING/FAILED/PASSED 五种状态文案和按钮权限。
- Flutter 工人端测试覆盖 PENDING/FAILED 可发起、INSPECTING/PASSED 不可重复发起。
- 构建部署后用生产现有已通过验收订单和工人模拟器验证。
