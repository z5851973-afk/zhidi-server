# 知底 Android 业主—工人真实闭环设计

## 目标

在不改动现有首页大框架的前提下，把业主端、工人端和 Spring Boot 后端收敛为一条以服务器/MySQL 为唯一事实来源的真实业务链路：

业主找师傅 → 查看真实资料和案例 → 邀请多个候选人 → 工人接单/拒单 → 双方确认上门时间 → 工人到达 → 工人提交服务端计价报价 → 业主比价并选择一人 → 施工日报 → 节点验收/整改 → 全部验收通过 → 付款记录 → 工人确认收款 → 完结。

## 不可破坏约束

- 首页现有信息架构、主要入口和已部署可用接口保持不变。
- 已上线数据不重置、不删除；数据库只允许 Flyway 前向迁移。
- 核心业务不得使用 Mock、Firestore、本地缓存或异常兜底制造“成功”。
- 金额由服务器计算；客户端仅提交业务输入并展示服务器结果。
- 所有跨端状态均落 MySQL，刷新、重装、换手机后仍可恢复。
- 每次部署必须具备源码、JAR、配置和数据库备份以及明确回滚路径。

## 角色与主流程

### 业主

1. 登录后查看真实可接单工人列表。
2. 点击工人卡片查看全名、工种、年限、自我介绍和真实案例。
3. 为同一需求邀请多个候选人；未上门前可取消单个候选。
4. 查看各候选状态，收到接单、上门时间、到达、报价、整改和收款反馈。
5. 只在工人到场并提交报价后进行比价，选择一位工人；其他候选自动标记未选中。
6. 在“我的家”查看报价、施工日报、验收节点和付款记录。
7. 全部节点验收通过后才能进入付款步骤。
8. 在线支付未取得商户资质前，只允许记录线下付款；必须由工人再次确认实际收款，才算完结。

### 工人

1. 首次登录必须完善真实资料：全名、工种、从业年限、自我介绍、案例。
2. 查看服务器待接单，明确接受或拒绝。
3. 接单后提出上门时间，等待业主确认；到达后发起到场确认。
4. 按工种服务端价格项填写数量和说明，服务器计算报价总额。
5. 被选中后提交施工日报、发起节点验收；整改失败节点后重新申请。
6. 业主报告线下付款后，工人仅在实际到账后确认收款，订单完结。

## 数据真相与同步规则

- 工人目录、资料、案例、预约、报价、日报、验收、聊天、付款记录均来自后端 API。
- 本地仅作为展示缓存，缓存不能创建不存在的订单、通知或成功状态。
- 写操作失败时保留用户输入并明确显示失败原因和重试入口。
- 每次状态写入成功后，相关列表和详情必须重新从服务端拉取。
- 状态文本统一使用中文业务词，不直接向用户暴露枚举名或 `booking` 等技术词。

## 付款与结算边界

### 当前可真实交付

采用“线下付款、双方确认”的诚实模式：

- 全部验收节点通过后，业主可创建线下付款记录。
- 业主填写付款方式、凭证号/备注并确认“已线下付款”。
- 状态变为“待工人确认收款”，不能直接变成已支付。
- 工人实际收到钱后确认收款，服务器记录双方时间戳并创建零平台手续费的收款记录。
- 操作幂等、按角色鉴权，业主不能代替工人确认收款。

### 暂不伪造

微信/支付宝聚合支付、平台分账、提现、自动退款和正式清结算需要营业执照、商户号、合同、备案或供应商审核。取得条件前，按钮必须说明“暂未开通”，回调接口不能把订单标记为支付成功。

## 体验规则

- 采用美团/滴滴式的“单一主动作”：每个阶段只突出当前下一步。
- 业主卡片优先显示工种、年限、案例数、当前状态；没有真实评价时显示“暂无评价”，不生成虚假分数。
- 多候选页支持打开资料详情后再添加，不以“添加”代替了解工人。
- 危险操作（取消、拒绝报价、确认验收、报告已付款、确认收款）使用二次确认并展示后果。
- 空状态必须提供下一步入口；网络失败与真实空数据采用不同页面。
- 消息中心由真实业务事件驱动，点击消息能进入对应订单/报价/验收页面。

## 基础设施降级原则

- 短信未配置时只允许明确标记的开发/测试验证码；生产包不得向用户展示或自动填充验证码。
- COS 未配置时，服务器使用受控本地对象目录保存案例、日报和聊天图片，返回可访问的 HTTP URL；不得返回 `file://` 假地址。
- 推送供应商未配置时，应用通过前台刷新/轮询获得状态，但明确列为正式发布条件，不能声称离线实时推送已完成。
- HTTP 仅作为现有服务器过渡；正式发布必须配置域名、HTTPS 和网络安全策略。

## 验收门槛

- 后端单元/集成测试覆盖核心状态机、角色权限、幂等和非法跳转。
- Flutter analyze 和关键页面测试通过。
- 两个全新账号、两个独立模拟器完成整条链路，不能依赖历史测试数据。
- 服务重启后数据仍一致；重复点击不会重复创建报价、付款或结算。
- 部署后检查 health、OpenAPI、认证、工人目录和核心接口，并确认 systemd 无重启循环。
- 任何未取得外部资质的能力在最终报告单独列出。
