# 工人收入与已完工工地入口设计

## 目标

让工人在接单中心能够明确进入真实收入明细，并从“已完成”列表进入对应工地的只读完工档案，不再只有不可点击的摘要卡片。

## 页面与交互

### 收入入口

首页顶部继续展示服务端汇总的“可结算 / 质保金”，右侧增加“收入明细 >”提示，整块可点击并进入现有 `WorkerSettlementPage`。结算页继续展示待确认收款、可结算记录、质保金及报价明细。

### 已完工列表

已完成卡片展示工种、业主、地址、本单可结算金额与质保金，并增加“查看完工档案 >”。整张卡片可点击进入同一订单的详情。

### 完工档案

完成订单的详情标题改为“完工档案”，保留业主信息、工地需求和报价单，并增加三个只读入口：施工记录、验收记录、收入与质保金。施工日报页在只读模式下隐藏日期、输入、图片选择和提交按钮；验收页在只读模式下不自动创建节点、不显示发起验收操作。

完工后结束工人与业主的直接联系入口：底部删除“联系业主”，只保留通栏“查看收入明细”；业主手机号在完工档案中按前三位和后四位展示为 `133****4758`，不再暴露完整号码。未完成订单的联系能力保持不变。

## 数据来源

- 工地状态：`WorkerAppState.completedOrders`，来自服务器预约 `COMPLETED`。
- 本单收入：`SettlementModel.bookingId`。
- 本单质保金：`WarrantyRetentionModel.bookingId`。
- 报价、日报、验收：复用现有真实 API 和页面。

不新增 Mock，不修改后端或生产数据。

## 验证

Widget 测试覆盖收入入口提示、已完成卡片点击、按工地展示金额、完工档案只读入口、日报/验收只读约束、完工后隐藏联系入口和手机号脱敏；最后运行 Flutter 全量测试和静态检查，构建工人端 APK 并在模拟器复验。
