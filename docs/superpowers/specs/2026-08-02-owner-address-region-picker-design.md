# 业主地址省市区三级联动设计

## 目标

把业主地址表单中的“省份、城市、区县”从自由输入改为受控三级联动选择。首期只开放四川省和甘肃省，覆盖两省全部地级市（自治州）及县级区划，避免错别字、省市错配和无法匹配同城师傅的问题。

## 开放范围与数据基线

- 四川省：21 个市（州）、183 个县（市、区）。数据名称以四川省民政厅《四川省行政区划代码信息表（截至 2025 年 12 月 31 日）》为基线。
- 甘肃省：14 个市（州）、86 个县（市、区）。数量与名称以甘肃省政府、民政系统公开资料交叉核对。
- 只收录正式县级行政区，不把开发区、高新区、园区或兰州新区作为县区重复加入；详细园区地址由“详细地址”填写。
- 行政区划数据以独立、不可变的 Flutter 目录模块保存，地址页只消费目录接口，不在 Widget 中散落硬编码。

## 交互设计

1. 省份、城市、区县使用只读选择框，点击后打开底部选择面板，不再弹出文字键盘。
2. 省份面板只显示“四川省、甘肃省”。
3. 选择省份后才能选择城市；选择城市后才能选择区县。未选择上级时点击下级，提示“请先选择省份/城市”。
4. 切换省份时清空城市和区县；切换城市时清空区县，防止保留不属于新上级的值。
5. 城市和区县选择面板支持关键词搜索；搜索只作用于当前层级和当前上级范围。
6. 选中项显示勾选标记；返回表单后显示完整正式名称。
7. 编辑服务器旧地址时：若省市区组合仍在开放目录中，自动回显；若不在目录中，原文字可见但标记“当前地区暂未开放”，必须重新选择后才能保存。
8. 联系人、联系电话、详细地址和默认地址逻辑保持不变。

## 数据与保存规则

- 保存给现有地址 API 的仍是 `province/city/district` 正式中文名称，不改后端 JSON 和数据库结构。
- 保存前同时验证：省份已开放、城市属于省份、区县属于城市。前端即使被异常状态污染也不得发送错误组合。
- 网络保存失败继续保留表单输入和三级选择结果，不做本地假成功。
- 地址列表、默认地址和预约快照继续沿用现有服务端逻辑。

## 代码边界

- 新增 `lib/data/owner_service_regions.dart`：行政区划模型、两省目录和层级查询/组合校验。
- 修改 `lib/pages/profile/address_page.dart`：用三级选择器替换三个 `TextFormField`，保留现有表单与保存状态。
- 修改 `test/address_page_test.dart`，新增目录单元测试：覆盖省份限制、全量数量、联动清空、搜索、编辑回显、旧地址阻止保存和正确草稿提交。
- 不修改后端数据库，不清理或迁移历史地址，不扩大到其他省份。

## 验收标准

- 省份只出现四川省、甘肃省。
- 四川 21 个市州/183 个县级区划，甘肃 14 个市州/86 个县级区划，目录测试固定总数防止漏项。
- 任一城市只能看到自己的区县，切换上级后旧选择立即清空。
- 三级字段不唤起键盘，长列表可搜索，窄屏和大字体无溢出。
- 新增、编辑、失败重试、设默认仍通过既有地址接口和测试。
- Android 模拟器分别跑通一条四川地址和一条甘肃地址，并检查无红屏、布局溢出或 Flutter 异常。

## 明确不做

- 本期不开放全国省市区。
- 不把省市区目录做成后台动态配置。
- 不接入地图定位、逆地理编码或街道/乡镇四级选择。
- 不自动修改已有地址记录。
