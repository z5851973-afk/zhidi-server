# 知底 Android 真实业务闭环实施计划

> 依据 `2026-07-22-owner-led-production-closure-design.md` 执行。每项先补失败测试，再做最小实现；核心流程不得保留本地假成功。

## 1. 建立可重复验收基线

- 记录当前 Git 状态、Flutter/Java 版本、模拟器和服务端健康状态。
- 建立核心接口清单与角色/状态矩阵。
- 为登录、工人资料、候选预约、接单、上门、报价、选人、日报、验收、付款建立测试账号隔离方案。
- 验证已有数据库迁移版本，不重建数据库。

## 2. 清除核心流程的假数据和双真相

- 为 OwnerAppState、WorkerAppState 增加远端失败/空数据测试。
- 删除预约和日报中与服务器数据混合的本地种子记录。
- 删除预约创建后的 Firestore 非权威同步。
- 工人目录和详情生产路径不再展示 Mock 评分、评价、距离、接单数或案例。
- 网络失败保留错误态和重试，不降级为“操作成功”。
- 统一业务枚举中文映射和错误信息。

## 3. 完整接通工人资料和案例

- 测试首次登录资料完整性校验以及缺失字段阻止接单。
- 验证工人全名、工种、年限、自我介绍、案例均落库。
- 业主目录卡片与详情只读取真实字段。
- 候选列表卡片可进入工人详情，返回后保持选择状态。
- 无案例、无评价时展示诚实空状态。

## 4. 固化多候选预约和双方取消

- 覆盖同一需求邀请多名工人、重复邀请幂等、单候选取消和权限测试。
- 业主在未上门前可取消；工人在允许阶段可取消/拒绝并填写原因。
- 取消后双方列表、详情和消息一致刷新。
- 已到场、已报价、已选中后的非法取消由服务端拒绝并给出可理解提示。

## 5. 固化上门时间、到达与报价比选

- 覆盖工人提出时间、业主确认/拒绝重约、工人到达、业主确认到场。
- 报价项从服务器价格表读取，数量/单位/金额校验在后端完成。
- 工人提交报价、业主拒绝重报、再次提交形成版本历史。
- 业主仅能比较同一需求的候选报价并选择一人。
- 选中者进入施工，其他候选自动变为未选中；双方收到真实业务消息。

## 6. 完成施工日报、验收和整改闭环

- 覆盖日报创建、图片上传、业主查看及失败重试。
- 覆盖验收节点创建、申请验收、通过、驳回、整改和再次申请。
- 仅全部节点通过后允许付款；没有节点或存在未通过节点必须拒绝。
- “我的家”和工人订单详情显示同一进度和下一步动作。

## 7. 实现无资质依赖的线下付款确认闭环

- 新增 Flyway 前向迁移，保存付款模式、业主报告时间、付款参考信息、工人确认收款时间。
- PaymentOrder 增加“业主已报告付款/待工人确认”状态；最终 PAID 只能由对应工人确认。
- 线下付款平台手续费为 0，不伪造平台分账。
- 增加业主报告付款和工人确认收款 API，覆盖鉴权、状态校验、幂等和并发。
- 工人确认后创建已收款记录，禁止后台无凭据直接标记结算成功。
- 业主端和工人端分别实现二次确认、结果页和跨端刷新。

## 8. 真实图片、聊天和消息

- 为通用上传实现 ECS 本地存储兜底，替换生产 `file://dev` 地址。
- 校验文件类型、大小、路径穿越和访问 URL。
- 验证文字聊天、图片聊天的 REST 历史和 WebSocket 鉴权。
- 业务状态变化生成去重消息，消息点击直达对应详情。
- 无推送资质时采用前台刷新/短轮询，离线推送列入外部条件。

## 9. 管理和运维安全

- 检查后台 API 的管理员鉴权、状态变更审计和分页。
- 禁止无实际付款证据的“标记已结算”。
- 补充关键异常日志、请求关联信息和健康检查。
- 根路径、未知路径、业务异常与数据库异常返回正确 HTTP 状态，不泄露堆栈。

## 10. 构建、部署和最终复验

- 运行后端测试、Flutter 测试、静态分析和 Android 构建。
- 构建 owner/worker 独立 APK，确认包名、API 地址和无开发验证码泄露。
- 备份生产 JAR、配置和数据库；上传新 JAR，systemd 启动并检查回滚点。
- 用两个独立模拟器、两个新账号从注册走到工人确认收款。
- 复测取消、拒绝重报、断网重试、重复点击、应用重启和服务重启。
- 更新 `PROJECT_STATUS.md`，输出已完成能力、APK 路径、部署版本、验证证据以及需要营业执照/商户资质/域名备案/供应商审核的剩余项。
