# 知底 Android 双端产品与体验审查

日期：2026-07-19

## 范围

本次依据当前源码、`PROJECT_STATUS.md`、生产服务器能力，以及本轮重新截取的业主师傅详情、候选选择、工人接单中心和工人个人中心界面进行审查。

## 产品功能地图

### 业主端

- 手机验证码注册/登录、首次资料完善、资料保存与退出登录。
- 首页装修入口、透明工价、找师傅、真实工人目录与详情。
- 查看工人姓名、工种、城市、经验、日薪、自我介绍及真实施工案例。
- 创建服务需求、最多添加三位候选、完成选择并进入“我的家”。
- 真实预约、工人接单反馈、双方取消、上门时间协商与到场确认。
- 查看多人报价、比价、二次确认最终选人。
- 查看施工日报、节点验收并提交验收结果。
- 消息、收藏、地址、售后等页面已存在，但部分仍是本地状态或未形成生产闭环。

### 工人端

- 手机验证码注册/登录、首次完善姓名/工种/工龄/城市/日薪/自我介绍。
- 维护个人资料和真实施工案例图片。
- 接单中心查看云端待接单、进行中和已完成订单。
- 接单、拒单、取消；提出上门时间并确认到达。
- 按服务器固定价目录提交报价。
- 被业主选中后提交施工日报、发起节点验收并查看结果。
- 收入、结算、消息和个人中心页面已存在；真实支付、结算和系统推送尚未接通。

## 技术框架

- 客户端：一个 Flutter 工程，通过 Android flavor 分成 owner 和 worker 两个 APK。
- 客户端状态：`OwnerAppState` 与 `WorkerAppState` 管理角色数据、会话和本地缓存；安全会话使用 Android 安全存储。
- 网络：Flutter API Client 直连 `http://47.109.0.191:8080`。
- 后端：Java 21、Spring Boot 3.5、Spring Security/JWT、Spring Data JPA、Flyway。
- 数据库：阿里云 ECS 上的原生 MySQL。
- 部署：systemd 托管 Spring Boot jar，无容器；案例图片目前存 ECS 本地目录。
- 现存边界：核心预约/报价/日报/验收已有 REST 链路，但部分页面仍包含本地状态、Mock 或旧 Firestore 桥接。

## 体验结论

### 业主端

易懂程度：7/10。主流程名称基本符合装修用户语言，“找师傅—候选—我的家—报价—验收”的方向清楚；候选完成按钮补齐后，下一步明显改善。

主要问题：师傅详情混入模拟评分、模拟评价、固定预约人数、0km 距离和模板文案，用户会误以为平台真的核验过这些数据；候选页仍出现 `demolition` 等英文后端值，削弱专业感；候选卡片虽然可以点击，但缺少“查看资料”文字或箭头提示。

### 工人端

易懂程度：6.5/10。底部只有接单中心、消息、我的三个入口，结构简单；订单按待接单、进行中、已完成分类，符合工人心智。

主要问题：没有订单时页面大面积空白，只说明“会通知”，没有刷新、完善资料、检查接单城市等可执行建议；收入与结算数字占据顶部，但没有解释统计周期；个人中心把施工案例入口藏在“个人资料”之后，工人不容易意识到案例会影响业主选择。

## 视觉评价

整体：7/10。暖白背景、橙色主色、圆角卡片和大触控区域形成稳定的装修服务品牌感；双端底部导航、按钮和卡片语言基本一致，三键导航安全区已经处理。

优点：层级明显、主按钮醒目、中文字号适合普通用户、卡片留白充足、绿色已选状态容易识别。

问题：部分界面留白过多；灰色辅助文字偏浅；业主详情信息密度偏高而工人端过空，双端成熟度不均；候选列表只显示姓名和工种，缺少经验、日薪、案例数等对比信息；英文 API 枚举与中文界面混用。

## 可访问性风险

- 浅灰辅助文字在暖白背景上可能对比不足，需要用工具测量 WCAG 对比度。
- 候选卡整卡可点击，但视觉上没有明确“查看详情”提示，辅助技术语义也需要验证。
- “已选”同时有文字和图标，比只用颜色更可靠；按钮和底部导航触控面积较大，这是优点。
- 截图不能证明 TalkBack 阅读顺序、动态字体 200%、焦点恢复和错误提示朗读，需要真机专项测试。

## 优先整改

1. P0：清除师傅详情中的模拟评分、模拟评价、固定预约人数、假距离和“系统优选”等不可证明数据；没有真实数据就显示真实空状态。
2. P0：所有后端工种/状态值统一转换为中文，不允许 `demolition`、`plumbing` 出现在用户界面。
3. P0：完成候选、预约、上门、报价、验收的双真机持久化复验，清缓存后仍从服务器恢复。
4. P1：候选卡补充经验、参考日薪、案例数和“查看资料”提示，支持更有效的横向选择。
5. P1：工人空状态增加“刷新订单”“检查服务城市”“完善案例”等明确动作。
6. P1：把工人“施工案例”提升为个人中心独立入口，并显示案例完整度。
7. P1：统一错误提示中文化，保留可复制的 trace ID 供客服排查，不直接显示内部 exception。
8. P2：统一灰色文本对比度、卡片间距、空状态高度和双端信息密度。
